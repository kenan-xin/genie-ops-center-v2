PROTOTYPE - throwaway, in-memory, not product code

One workflow builder, many approval flows

Question. Can one workflow builder (the approvals module) run both the legal agreement review and a new IT access request, with no code change, and does each piece land in the right part of Ops Center? The four boxes below are the four places code or configuration lives. Every effect in the log is tagged with the part that handles it. Try the walkthroughs, then press buttons freely. Watch the Event log: if something is handled by the wrong part, the split is wrong.

Where each piece lives

Core platformSign-in and people, roles and groups, can() access check, files, background jobs, audit, notifications inbox, outbound HTTP with secrets from the environment (secret_ref). Knows nothing about workflows.
Approvals module (the builder)Workflow definitions and versions, steps (approval, IF, HTTP, end), one form per workflow, cases, the engine that moves a case forward, backups and delegation. Knows nothing about contracts or IT.
Contracts moduleThe master register and register numbers. Listens for "case finished" events from workflows tagged contract. Never imports the approvals module.
Customer configurationThe two workflows below are data: drawn in the builder, or seeded from the customer folder. Adding the IT request needs no new code.

The portal sidebar, per person

Signed in as

Each published workflow becomes one sidebar entry. Who sees it is a normal Ops Center role assignment, scoped to that workflow, given to a person or to a group. This is the same mechanism Solutions uses for solution:<id>. Inside a workflow, who approves each step is workflow configuration, and who can see a case comes from the person's relationship to it.
