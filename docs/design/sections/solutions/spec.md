# Solutions Specification

## Overview
The first platform module. The hub is the member landing page after sign-in; core has no page of its own there. Members open it to see the solutions they are granted, grouped by category, with recents, favorites, search, sort, and a status filter, and open one solution at a time in the viewer. A solution is one of two types: `chat`, a streaming conversation through a server-side proxy to the external Genie chat API with a chat theme, welcome text, starter prompts, and optional feedback; or `embedded`, an external web application shown in a sandboxed iframe at a public HTTPS URL. Administrators register and configure solutions of both types, manage status, build chat themes with a live preview, and read who has access to what. Categories are core; administrators manage them on the Categories page of the admin portal (DEC-51). A solution references a core category by id, and a deleted category leaves the solution ungrouped. Genie keeps one session handle per person per chat solution, never the transcript. Designed mobile first; the phone layout is the base and the desktop layout adds columns.

## User Flows
- Member lands on the Solutions hub after sign-in. Only granted solutions appear, grouped under category headers. A category with none is hidden. Solutions with no category sit under an Other heading after the categories. A Recents row (at most six) appears above the categories only when there are recents. Each card carries a type label (Chat or Embedded).
- Member searches by name or description, sorts by recently opened or name, and filters by status. The status filter appears only when at least one visible solution is not Ready. A filter with no results shows an empty state with Clear filters.
- Member with no granted solutions sees the Solutions hub empty state: "No solutions yet", "Ask your administrator to grant you access to a solution.", and the support contact when branding provides one.
- Member stars a solution from its card. It joins the pinned rail in the sidebar (up to six) and the Favorites page.
- Member opens Favorites from the sidebar and sees the starred solutions in sidebar order. They move one up or down (drag on desktop, arrow buttons for keyboard and phones), open one, or unstar one; unstar shows a 4-second toast with Undo that restores it.
- Member opens a chat solution. The viewer header shows a back link to Solutions, the monogram, name, type label, status pill, favorite star, a Focus toggle, and New chat. Below the header, the first visit shows the welcome text and starter prompt chips. Reopening a solution resumes the same conversation on the bot's side and shows the welcome state with the line "Continuing your earlier conversation. Earlier messages are not shown."
- Member sends a message. The composer shows a sending state until the reply stream ends or Stop is pressed. A second send is blocked while one message is in flight. If the reply carries a reasoning block, a collapsible "Thinking" disclosure streams above the answer and collapses to "Thought for N s" when the answer begins; it can be reopened. An interrupted reasoning stream is labeled "Reasoning interrupted".
- Member's reply ends without a finish signal. The message is labeled "Incomplete response". A failed send shows a safe error with Retry; Send stays disabled until Retry or New chat.
- Member presses New chat. A confirm step warns that the current conversation is discarded, then a fresh conversation starts. New chat is disabled while a reply is streaming.
- Member uses thumbs up or down on an assistant reply when the solution has feedback enabled. Down shows a short thank-you toast. Nothing else changes on screen.
- Member opens an embedded solution. The viewer shows the same header and the external application in a frame that fills the rest of the page. A Fullscreen control appears when the solution allows it. While the frame loads, a skeleton shows; if the frame fails to load, a notice offers Reload.
- Member turns on Focus. The shell navigation hides and the viewer takes the full width, with an Exit focus control in the header. On phones the viewer is always full width and the toggle is hidden.
- Member opens a solution in Maintenance or Down. The viewer shows a status notice with the administrator's reason instead of the composer or frame: Maintenance amber, Down red. Nothing streams.
- Member with no grants sees the No solutions empty state from the Account and Inbox section.
- Administrator opens Solutions in the admin portal, sees every solution including Draft and Archived (behind a toggle), searches, sorts by updated (default), name, or status, and filters by type, status, and category.
- Administrator registers a solution in a dialog with name, description, category, and type (Chat or Embedded), then the connection fields of that type: for Chat the external bot id, the API endpoint (prefilled with the deployment's usual address), and the feedback switch; for Embedded the application URL and the Allow fullscreen switch. The connection fields are required to register, so a new Draft is usable from Configure onward. Theme, welcome text, and starter prompts are set in Configure. It starts as Draft, visible to administrators only. The slug is derived from the name once and never changes.
- Administrator configures a solution in a right slide-over. Tabs for a chat solution: General (name, description, category, monogram, accent color with contrast check), Chat (chat theme, welcome message, starter prompts up to 12 of 200 characters each, feedback toggle), Connection (external bot id, API endpoint as a full HTTPS URL), Status, Access. Tabs for an embedded solution: General, Connection (iframe URL, allow fullscreen), Status, Access.
- Administrator changes the external bot id or endpoint of a chat solution. A warning states that every member's current conversation restarts because the stored session handles are invalidated, and asks to confirm.
- Administrator changes status. Members see Ready, Maintenance, and Down. Archive hides the solution from members while keeping its data. Draft is visible to administrators only.
- Administrator previews any solution, including Draft, with Preview as member. The preview carries a labeled banner reading "Previewing as a member. This preview is recorded and does not count as access." for every status; a Draft pill joins it only when the solution is Draft. The preview works for both types, is written to the audit log, and is never counted as access.
- Administrator duplicates a solution as a new Draft with " (copy)" appended to the name, or permanently deletes an archived solution after a confirm dialog that names what is removed with it: favorites, recents, and session handles.
- Every destructive step is the confirm dialog from `design-system/tokens.md`: Archive, theme Delete, New chat, and the permanent Delete. The object is in the title, one sentence states the consequence, Cancel is focused, and the action button carries the danger tone.
- Administrator reads the Access tab: people and groups with a role carrying `solutions:use` scoped to this solution or tenant-wide, with the source of each grant, and an Add access shortcut that opens the assignment form with the role and scope preselected.
- Administrator opens Access overview, picks a solution or a person, and sees effective access with its source: which role, which scope, direct or via which group. Empty states for a person with no access and a solution with no grants each offer Add access.
- Administrator opens Chat themes, sees the saved themes strip with the tenant branding as the undeletable default, selects one, and edits header color and its text color, user and assistant bubble colors and their text colors, corner radius from 0 to 28, font from the approved list, and input placeholder, with a live chat preview that toggles between phone and desktop framing. Every color pair passes the same contrast check as Branding, and Save is blocked while any pair fails. The Tenant branding chip is a client-side seed rendered from the tenant branding values, not a stored theme row, and there is no default flag in `chat_theme`. A new theme copies those values. A solution with `chatThemeId` null renders with the branding seed. A theme is deleted only when no solution uses it. The panel lists which solutions use the theme.

## UI Requirements
- Favorites page (workspace chrome, `/favorites`): ordered list, one column at every width, card rows on phones. Each row: position number, drag handle (visual) with up and down arrow buttons, monogram, name, type pill, category, status pill when not Ready, Open button, and an Unstar star. A note above the list says the first six appear in the sidebar Pinned rail. Empty state "No favorites yet" with "Star a solution on the Solutions hub to pin it here."
- Hub: page title Solutions with the description from the shell. Empty state when the member has no granted solutions (see the flow above). Search field, sort select, and, when needed, a status filter on the top row. Recents as a horizontal row of compact cards. Category sections with a header (name, count) and a responsive card grid (one column on phones, two on tablets, three or four on desktop).
- Solution card: monogram tile in the solution's accent color with computed foreground, name, type label (Chat or Embedded) as a gray pill, one-line description clamped to two lines, status pill when not Ready (Maintenance amber, Down red), favorite star toggle in the corner that does not open the card. Whole card is the open target. Draft badge on cards visible to administrators only.
- Viewer header: back link to Solutions, monogram tile, name, type label, status pill, favorite star, Focus toggle, and New chat for chat solutions or Fullscreen for embedded solutions that allow it. The name and its type pill share one row and the name truncates, so the pill never wraps under the monogram. Focus does not render below 768px; below 640px New chat moves into the overflow menu.
- Chat body: assistant messages left with the theme's assistant bubble, user messages right with the user bubble, and a small gray time always visible under the last bubble of each run of messages from the same side within five minutes (never hover-only; phones have no hover, DEC-25). A reasoning disclosure above an assistant message when present. Before the first message: welcome text and starter prompt chips centered; on reopen, the continuing-conversation line under the welcome text. Composer pinned to the bottom above the keyboard on phones, with a growing textarea, Send, and Stop while streaming. Helper line under the composer: solution name and a note that replies may be wrong.
- Chat viewer states: Maintenance notice (amber) with reason, no composer. Down notice (red) with reason, no composer. Draft preview badge for administrators with a note that members cannot see it. Streaming reply shows a blinking caret at the end. Incomplete response label on a truncated reply. Error on send shows an inline safe message with Retry and disables Send.
- Embedded body: the frame fills the area under the header, with a loading skeleton, a failure notice with Reload, and the Fullscreen control when allowed. No composer, no theme. The sandbox note above the frame is hidden below 640px and its URL truncates, so nothing overflows on a phone.
- Embedded card and header decision: an embedded solution shows the Embedded type pill only, with its accent monogram; it carries no theme, no theme name in the admin table, and is never counted in a theme's Used by.
- Rich text in replies: sanitized markdown with `https:` and `mailto:` links only, no inline styles, the bot's known color spans rendered as semantic tones, and fenced Mermaid and Vega-Lite blocks rendered as diagrams and charts with a plain code fallback.
- Admin Solutions table: solution (monogram, name, description truncated), type, category, status pill, theme (chat only, hidden below 1280px), access count, updated. Every column fits at 1280px without horizontal scrolling. Sort and filters in the toolbar. Row click opens the configure slide-over. Row overflow menu: Duplicate as draft, Archive or Restore, Delete (archived only). Show archived toggle. Register solution primary button. On phones the table is a card list.
- Register dialog: name (at most 80 characters), description (at most 500), category select, type radio (Chat, Embedded) with one line each, then a type-specific block that swaps with the radio. Chat connection: external bot id (mono, at most 200 characters, required), API endpoint (mono, prefilled, validated as a public HTTPS URL whose origin the deployment allows), Feedback switch (default on). Embedded application: application URL (mono, required, validated as a public HTTPS URL), Allow fullscreen switch (default off). Register as draft is disabled until the type block is valid. The monogram defaults to the initials of the first two words of the name. When the deployment has chat streaming disabled the dialog opens on Embedded and the Chat radio is disabled. Note that the solution starts as Draft.
- Limits are enforced in the inputs, each with a counter: name 80, description 500, external bot id 200, welcome text 2000, starter prompt 200, theme placeholder 140, composer prompt 8000. A changed field carries the unsaved blue dot on its label.
- Phone primary action (Register solution) sits in the sticky bottom bar under 768px, not inline in the page (`DEC-25`).
- Configure slide-over: about 560px on desktop, a full-height sheet on phones. Header with monogram, name, type, status pill, and Preview as member link. Tabs depend on type as listed above. Save per tab with a dirty indicator. Contrast check on accent color and foreground, same as Branding. Connection tab for chat: external bot id and API endpoint as mono text fields, the endpoint validated as a public HTTPS URL whose origin the deployment allows (the error names the origin, never the list), and the invalidation warning on change of either. When the deployment has chat streaming disabled, the Register dialog's Chat type and the Connection tab show a notice: "Chat solutions are not enabled on this deployment. Contact your Genie operator." Connection tab for embedded: iframe URL validated as a public HTTPS URL, and an Allow fullscreen switch. Status tab is a radio list with a reason textarea for Maintenance and Down and an Archive action separated at the bottom.
- Access overview: two pickers at the top, Solution or Person, then a table (card list on phones) of effective access rows: principal or solution, role, scope, source (direct, via group), added by. Empty states as above.
- Chat themes: strip of saved theme chips (name, three color dots) with the Tenant branding chip first (a client-side seed from the branding values, not a row; no default flag) and a New theme button. Controls: header color with text color and contrast pill, user bubble pair, assistant bubble pair, radius slider 0 to 28, font select, placeholder input. Live preview with a Phone and Desktop toggle rendering a short sample conversation with the composer. Footer with Used by n solutions, Save, Delete (disabled when in use or default).
- All screens in the shell: workspace chrome for hub and viewer, admin chrome for Solutions, Access overview, Chat themes. Tokens per `../../design-system/tokens.md`.
- Out of scope: conversation history or a conversation list, transcript storage, a separate presenter mode or sidebar-only collapse (Focus mode replaces them), custom CSS in themes, theme presets, a status-page link in the Down notice, attachments, and a third solution type.
