# Branding Specification

## Overview
The admin pages where a tenant administrator sets how Genie looks for their people: identity, one primary color and theme, typography (font, font size preset, light-theme text color), the sign-in page, emails, footer links, and locale. Seven tabs edit one browser-side draft with a live preview that shows each setting where it lands. One Publish applies everything at once and writes one audit event. Nothing from branding is written to the Keycloak realm (DEC-40): the realm display name is the company name set by provisioning (`genie-ops setup`), and the realm SMTP settings carry the sender name and reply-to. Everything outside these controls is fixed by the design system.

## User Flows
- Administrator opens Branding and lands on the Identity tab. The right pane shows a mini shell preview (sidebar, header, a card, a button) with the current branding and a light or dark toggle.
- Administrator edits any field on any tab. The change appears in the preview at once, the preview carries a small Draft label, and the page header shows an Unpublished changes indicator with the count of changed fields.
- Administrator closes or reloads the tab with unpublished changes. The browser's own `beforeunload` prompt asks to leave or stay; there is no in-app leave dialog.
- Administrator presses Publish. A confirm dialog titled "Publish 3 changes?" lists the changed fields by tab, states the one consequence (members see the new branding on their next page load), and focuses Cancel. On confirm the branding row is written in one transaction and one audit event lists the changed fields.
- Administrator presses Discard. The same confirm dialog in the danger tone ("Discard 3 changes?") lists the same changed fields by tab, says the changes are lost, and drops the whole draft on confirm.
- Administrator presses the published pill in the header, which reads "Published 2 hours ago by Priya Nair". A dialog names who published and when, lists each field the last publish changed with its value before and after, and offers Restore. Restore writes the previous values into the draft and nothing else: the admin reviews them on the tabs and presses Publish to apply them. The dialog carries a Simulated pill because no platform read returns previous values yet.
- Administrator uploads a logo, square mark, favicon, or sign-in background in a drop zone. The zone states accepted types, the 15 MB limit (DEC-44), and recommended dimensions. The file uploads through Genie in one request: the slot shows the file name and a progress bar while it uploads, then the image with Replace and Remove and a scan status of Scanning (platform value `pending`), Clean, or Skipped. SVG, PNG, JPEG, and WebP are accepted by type; SVG uploads are sanitized in core on upload (`DEC-20`); the scan status stays Skipped until a scanner exists. The zone says so. An infected file never reaches the slot: the zone shows a refusal notice with `role="alert"` reading "This file was refused by the malware scan.", with Choose another file and Dismiss. A Scanning image is not shown to members, in the preview, or in the emails until it is Clean or Skipped.
- Administrator sets the primary color by hex or picker. It shows its computed foreground and one contrast pill per rendered pair. There is no tint strip: `DEC-47` derives no ramp, so hover and press are the same color at 90% and 80% opacity. A failing pair shows a Fix action that suggests the nearest shade that passes by changing lightness only, so the hue is kept. Publish is blocked while a pair fails.
- The checked pairs are every place the color actually renders, not the fill alone: the fill against its computed foreground in light and in dark at 4.5:1, the color as text on the white active navigation pill in light and on gray-900 in dark at 4.5:1, the count pill fill against white text at 4.5:1, and the focus ring against white and against gray-50 at 3:1 (WCAG 1.4.11). A color that passes the fill pair can still fail as text, which is why each pair carries its own pill.
- Administrator picks the default theme (Light, Dark, System).
- Administrator opens Typography and picks a font from the approved list, a font size preset (Compact 14 px, Default 15 px, Large 16 px) with a sample sentence at that size, and the text color for light surfaces by hex or picker. A sample block renders a heading, a paragraph, and a label in the chosen font, size, and color on white and on the gray-50 subtle surface. Two contrast pills check the text color against white and against gray-50 at 4.5:1; a failing pill shows Fix, which moves lightness and keeps the hue. Publish is blocked while a check fails. The text color is not applied in the dark theme, which keeps gray-100; the tab says so.
- Administrator edits the sign-in page: background color or image, welcome text, support contact, system-use notice text, and whether acknowledgement is required. The preview shows the sign-in card.
- Administrator edits email settings: sender display name, reply-to, footer text. The sender address itself is the deployment's `MAIL_FROM` (`no-reply@genie.example` in the sample) and is not editable. For a local-accounts tenant the sender name and reply-to also apply to the realm's SMTP settings. The preview renders the real invitation template, in the same mail-client frame and body component the email gallery uses, with the draft values. The email stays light when the preview theme is dark.
- Administrator edits links: support URL or email, terms of use URL, privacy policy URL. The preview shows the shell footer and notes that the support contact set here is the one shown on the sign-in page and in every email footer.
- Administrator edits locale: default language from the available list, time zone, date format, number format. The preview shows language, time zone, and formatted date, time, and number samples. There is no currency row; currency is not a branding field.

## UI Requirements
- Renders in the admin portal chrome. Page header: title Branding, description, and on the right the Unpublished changes indicator, Discard, and Publish. Publish disabled when nothing changed or a contrast pair fails, with a tooltip saying why. Under 768px Discard and Publish move out of the header into a sticky bottom bar on the page.
- Contextual help (design system, Help disclosure): one collapsed button in the header row, beside the unpublished or published pill, labeled How publishing works. It says that the draft lives in this browser and nobody else sees it, that Publish writes every changed field at once and records one audit event that members meet on their next page load, and that Discard drops the draft while Restore only fills it for the administrator to publish.
- Layout: left column with a tab strip (Identity, Colors and theme, Typography, Sign-in page, Email, Links, Locale) and the tab's form in a card. Right column with the preview card, sticky, with a Light and Dark segmented toggle, a Draft pill while unpublished, and a caption naming what the preview shows. On narrow screens the preview stacks under the form.
- Identity tab: company name, product display name, and four image drop zones: logo for light backgrounds, logo for dark backgrounds, square mark, favicon. Each zone: dashed border, icon, accepted types, limit, recommended size, then the uploaded image with Replace and Remove and a scan status pill. The Scanning and Infected states are kept in the design but are not reachable in the first release: `scan_status` stays `skipped` until a scanner exists, and the implementer must not fake them. Square mark and favicon previews show the actual image at 16, 32, and 48 pixels once the scan has passed; the shell, sign-in, and email previews show the same image in place of the letter tile. A fallback note says the letter tile is used when no mark is set.
- Colors and theme tab: one color row with a picker, hex input, and computed foreground swatch, then one contrast pill per pair from the list above, each labeled with the pair it checks (Fill light, Fill dark, Text on nav light, Text on nav dark, Count pill, Focus ring). A failing pill is red with a Fix button next to it. No tint strip. Below: default theme segmented control.
- Typography tab: font select; Font size segmented control (Compact, Default, Large) with a one-line sample at the chosen size; Text color row with picker, hex input, White and Subtle contrast pills at 4.5:1, and Fix when one fails. Under it a sample block (heading, paragraph, label) in the chosen font, size, and color on white and on gray-50. A hint states that the size preset sets the root size and that the text color applies to light surfaces only; dark keeps gray-100.
- Sign-in page tab: background choice (color or image drop zone), welcome text, support contact, system-use notice textarea, acknowledgement toggle. Preview is the sign-in card with the draft values.
- Email tab: sender display name, reply-to address, footer text. Preview is the rendered invitation email inside a mail-client frame, using the draft mark, primary color, sender name, and footer. A note says that for a local-accounts tenant the sender name and reply-to also apply to the realm's SMTP settings; that the credential emails (set password, reset password, verify email) are Keycloak's built-in templates and print the realm display name only; and that nothing else from branding reaches them.
- Links tab: support URL, support email, terms URL, privacy URL, each validated as a URL or email. Preview is the shell footer strip.
- Locale tab: language select, time zone searchable select, date format and number format selects. Preview shows today's date, the current time, and 1234567.89 formatted with the draft values.
- Draft handling: every field change updates one draft object. Changed fields carry a small dot on their label. Discard resets all. A beforeunload prompt guards unpublished changes.
- Publish and Discard confirms use one `ConfirmDialog` (title naming the object and count, one consequence sentence, Cancel focused, danger tone for Discard). Both list the same changed fields as human labels grouped by tab, for example "Colors and theme: Primary color, Default theme", so the two decisions read against the same set.
- The published pill is a button while the draft is clean and opens the previous-values dialog. The dialog uses the same `ConfirmDialog` with `role="dialog"`, Close in place of Cancel, and Restore as the action. It lists each changed field with "Before" and "Now", and Restore is disabled when no previous value was recorded. Restoring shows the toast "Restored to the draft. Publish to apply." While the draft is dirty the header shows the unpublished-changes pill instead, so Restore is reached from the published state only.
- Previous values are not in the platform today: `lastPublish` records which fields changed, not what they held. `LastPublish.previousValues` is the read the design assumes, the design runs it on the sample fixture, and the dialog says so with a Simulated pill and one line of explanation. The implementer must not ship Restore before that read exists.
- Tab strip: labels Identity, Colors, Typography, Sign-in, Email, Links, Locale so all seven fit at 1024px. On phones the strip scrolls with a fade edge and the active tab stays in view. The preview collapses behind a "Show preview" toggle on phones so the form is reachable without scrolling past it.
- Locale tab: with one language available the language select is disabled with the note "English. More languages when a customer requires them."
- Colors tab: the Dark contrast pill shows the derived hex the shell uses on dark surfaces under the pill.
- Designed mobile first; phone layout is the base and the desktop layout adds columns. After publish a toast reads Published.
- Tokens: blue actions, semantic pills, gray neutrals, rounded-xl cards, rounded-lg controls, Plus Jakarta Sans, JetBrains Mono for hex values.
- Out of scope: font upload, custom CSS, per-realm Keycloak page theming, crop or resize tools, and a CSS token export.

## Design notes
- The tenant primary fills the shadcn `--primary` and `--primary-foreground` variables per request. In this design tree, `blue-600` on active nav rows, primary buttons, focus rings, and count pills stands for `--primary`; the export maps those classes to `bg-primary`, `text-primary-foreground`, and `ring-primary`. Sidebar and page chrome never take the tenant color. Solution monograms keep their own per-solution color.
- SVG uploads are sanitized in core on upload (`DEC-20`); the design shows no sanitizing state.
- Typography: the tenant font, one of three root font sizes (14, 15, 16 px; the scale is rem-based), and a light-theme text color that fills `--foreground`; checked at 4.5:1 against both light surfaces; dark keeps the fixed gray-100.
