# Design Review, 2026-09-16

Status, 2026-09-17: applied in full. Superseded by `review-2026-09-16-final.md`, which records the verification; do not work from this file.

Scope: shell, sign-in and tenant pages, account and inbox, people groups and roles, chat solutions, branding. Reviewed against the platform decisions in the `genie-ops-center-v2` repository (`docs/core/vision.md`, `docs/core/decision-log.md`, `docs/architecture/data-shape.md`, `docs/architecture/module-contract.md`).

State of the repository: `tsc -b` passes, `eslint src/sections src/shell` passes. Every issue below is a design or consistency defect, not a build error. Fix them in the order given; the first group changes every screen.

Rules for the fix pass: do not name customers, do not reference the previous codebase, name a module by its capability, write "identity provider" unless Microsoft Entra ID is the deliberate example, and follow the token rules already in the specs (blue for actions, semantic colors only for real status, Plus Jakarta Sans, JetBrains Mono for identifiers).

## A. Mobile first (every section)

Decision `DEC-25`: every screen, including the admin console, is designed at phone width first. Tables become card lists, inspectors become full-height sheets, primary actions sit in a sticky bottom bar when a page has one, and no action is desktop-only.

A1. Only one phone screenshot exists in the whole repository (`sign-in-page-mobile.png`). Produce a phone screenshot (390 by 844) for every screen that has a desktop screenshot, in every section, and keep both.

A2. Every data table uses `overflow-x-auto` (horizontal scroll) as its small-screen behavior. Replace with a card list under 768px in: `people-groups-and-roles/components/PeopleDirectory.tsx`, `GroupsDirectory.tsx`, `RolesDirectory.tsx`, `RoleDetail.tsx` (assignments), `chat-solutions/components/AdminSolutions.tsx`, `AccessOverview.tsx`, and the sessions tables in `account-and-inbox/components/AccountPage.tsx` and `PersonInspector.tsx`. Each card shows the row's identity, status pill, and the one or two facts a person scans for, with the row actions in an overflow menu.

A3. The shell code in `src/shell/components/AppShell.tsx` is desktop first (sidebar with a `lg:hidden` drawer fallback). Rebuild it to the revised `product/shell/spec.md`: phone layout is the base (54px header with tenant mark, page title, hamburger; full-height drawer capped at 84% width; sticky bottom action bar slot), tablet keeps the drawer, desktop adds the 240px sidebar. Add `product/shell/shell-mobile.png`, `shell-tablet.png`, and `shell-desktop.png` for both chromes.

A4. Every right slide-over (person inspector, group inspector, configure solution) must become a full-height sheet under 768px, with the close control reachable by thumb (bottom or top-right, at least 44px). Every dialog (add person, register solution, publish branding, assignment form, confirm steps) must be full-width on phones with actions in a bottom bar.

A5. Branding: the preview column stacks under the form on narrow screens (already in spec). Make the preview collapsible on phones with a "Show preview" toggle so the form is reachable without scrolling past the preview.

A6. Chat viewer on phones: composer pinned to the bottom above the keyboard, starter chips wrap to two lines, header collapses the description, New chat moves into an overflow menu.

## B. Sign-in and tenant pages

B1. Break-glass flow is missing the authenticator enrollment step. `DEC-24`: first sign-in forces a password change and authenticator-app enrollment. Add a step `authenticator-enroll` (QR code, manual key, confirm with one code) after the forced password change and before the console. Update `types.ts` (`BreakGlassStep`), `data.json` (`steps`), the component, the spec, and add `break-glass-sign-in-enroll.png`.

B2. Spec still lists `twoFactorEnabled` nowhere but the code path must not allow skipping the code step. Confirm the component renders the code step unconditionally and remove any prop that could disable it.

## C. Account and inbox

C1. Screenshots predate the last code change (language select hidden when one language). Regenerate `account-page.png` and `account-page-dark.png`.

C2. `AccountPage.tsx` hard-codes `TIME_ZONES`. Take the list from props (`preference.availableTimeZones`), sourced from the tenant's locale options, and add the field to `types.ts` and `data.json`.

C3. Sessions table: see A2. Also show the current session card first on phones.

C4. Profile block: for a local-accounts tenant, add a "Change password" link that opens the realm's account page (from `tenantSupport` or a new `accountManagementUrl` prop). Spec already names it in the shell user menu; the account page is the second place people look for it.

## D. People, groups, and roles

D1. Screenshots predate the spec changes (break-glass hidden, remove copy, phone card list). Regenerate all `people-*.png`, `groups-*.png`, `role-*.png`, and add phone versions.

D2. Add person dialog: when `tenantSettings.onboardingMode` is `jit`, the note changes to "People in your identity provider can also sign in without being added here"; when `invite`, keep "Pending until first sign-in". Confirm both texts render from `tenantSettings` and screenshot both.

D3. Role detail: the `Tenant administrator` system role must show a note that a module's admin permission is added to it automatically when the module is entitled (`DEC-23`). Show that key with an "added by entitlement" marker in the permission list.

D4. Person inspector, Roles tab: the source column must distinguish "Direct", "via <group>", and "via Tenant administrator (system)" so an administrator understands why they can reach a module admin screen.

D5. Assignment form record picker: when the chosen module is not entitled, the picker is disabled with a note, not empty.

## E. Chat solutions

E1. `viewer.isAdmin` contradicts `DEC-23` (there is no admin flag; only permissions). Rename to `viewer.permissions: string[]` and derive `canAdminister = permissions.includes('chat-solutions:admin')`. Draft badges, the Draft status filter, and the Preview as member link key off that permission. Update `types.ts`, `data.json`, components, spec.

E2. Conversation persistence is undefined. Genie stores only a session handle and no transcript, so a page reload cannot restore the messages. Decide and state in the spec: on reload the viewer starts a fresh conversation (the handle generation is bumped) and shows the welcome state with a one-line note "Conversations are not kept after you leave." Remove any implication that history returns.

E3. Withdrawn (`DEC-30`). The endpoint is one free-text field, `apiEndpoint`, validated as a public HTTPS URL. No approved origins list.

E4. Chat themes: the header color has no contrast check. Add `headerForeground` to `ChatTheme` and `ChatThemeInput`, show the computed foreground and a contrast pill on the header row like the bubble rows, and block Save while any pair fails, matching Branding.

E5. `ChatTheme.id` is `null` for the tenant-branding default. A null identifier breaks list keys and selection. Use the literal id `default` with `isDefault: true`; `Solution.chatThemeId` stays nullable meaning "use default".

E6. Hub: the status filter must appear only when at least one visible solution is not Ready (spec says so; `solutions-hub.png` shows it with the sample data, which is correct because Maintenance and Down exist; add a screenshot of the hub with all Ready to prove the filter hides).

E7. Viewer: add the streaming state screenshot at phone width and the Stop control; confirm a second send is blocked while streaming (disabled Send with a tooltip).

E8. Access overview: the note "Access is read from role assignments" is right. Add the empty state for a person with no access and for a solution with no grants, each with a link to add access.

## F. Branding

F1. Uploads: the spec, `types.ts` comments, and any UI copy still say "directly to object storage through a signed URL". `DEC-20` changed this: files upload through Genie in one request, bytes are stored in the tenant database by default. Replace with "uploads through Genie with a progress bar"; `BrandingImage.url` comment becomes "a tokenized download link issued by Genie".

F2. `ScanStatus` uses `scanning`; the platform enum is `pending | clean | infected | skipped`. Rename the value to `pending` and keep the UI label "Scanning".

F3. Publish dialog shows raw field keys (`accentColor`, `defaultTheme`). Show human labels grouped by tab ("Colors and theme: Accent color, Default theme").

F4. The tab strip truncates at 1280px ("Lo..." for Locale in `branding-colors-failing.png`). Let the strip wrap to two rows or shorten labels ("Colors", "Sign-in", "Email", "Links", "Locale") so all six fit at the 1024px breakpoint; on phones the strip scrolls with a fade edge and the active tab is always in view.

F5. Locale tab: with one language available (`DEC-13`), render the language select disabled with the note "English. More languages when a customer requires them." rather than an active select with one option.

F6. Identity tab: SVG is accepted only after sanitizing; the drop zone copy must say so. The favicon zone accepts ICO, PNG, SVG; make sure the 16, 32, 48 previews render the actual image, not a placeholder icon, when `url` is present.

F7. Colors tab: the "Dark" contrast pill checks a lifted shade the shell derives; show that derived hex under the pill so an administrator can see what dark surfaces will use.

H3. Sample data must not include a real customer name. Current data uses fictional tenants, which is correct; keep it that way.
